Applying Filters to SQL Queries

Tools of the Trade: Linux and SQL

Project description

I work as a security professional at a large organization. Part of my job is investigating security issues to help keep the system secure. I recently uncovered some potential security issues involving login attempts and employee machines. My task was to examine the organization's data in its employees and log_in_attempts tables, using SQL filters to retrieve records from different sets of data and investigate possible security issues.

01 / 06

Retrieve after-hours failed login attempts

Context

A potential security incident occurred after business hours. I needed to identify failed login attempts that happened after 18:00.

SQL
SELECT *
FROM log_in_attempts
WHERE login_time > '18:00'
AND success = FALSE;
Explanation

This query retrieves failed login attempts that occurred after 18:00. I used SELECT * to retrieve all data from the log_in_attempts table. The WHERE clause filters the results using two conditions. The first condition, login_time > '18:00', finds login attempts that happened after 18:00. The second condition, success = FALSE, finds unsuccessful login attempts. I used AND because both conditions had to be true.

02 / 06

Retrieve login attempts on specific dates

Context

A suspicious event occurred on 2022-05-09. I needed to investigate login attempts that occurred on that date or on the previous day, 2022-05-08.

SQL
SELECT *
FROM log_in_attempts
WHERE login_date = '2022-05-08'
OR login_date = '2022-05-09';
Explanation

This query retrieves login attempts from the two specific dates. I used SELECT * to retrieve all data from the log_in_attempts table. The WHERE clause filters the results by login_date. The first condition searches for login attempts on 2022-05-08, and the second searches for attempts on 2022-05-09. I used OR because a login attempt only needs to match one of the two dates.

03 / 06

Retrieve login attempts outside of Mexico

Context

Suspicious login activity was detected, but it was determined that the activity did not originate in Mexico. I needed to investigate all login attempts that occurred outside of Mexico.

SQL
SELECT *
FROM log_in_attempts
WHERE country NOT LIKE 'MEX%';
Explanation

This query retrieves login attempts that occurred outside of Mexico. I used SELECT * to retrieve all data from the log_in_attempts table. The WHERE clause filters the results by the country column. I used NOT LIKE 'MEX%' because Mexico can appear as MEX or MEXICO. The % wildcard includes any characters that come after MEX, and NOT LIKE excludes these values from the results.

04 / 06

Retrieve employees in Marketing

Context

The security team needed to update specific computers used by employees in the Marketing department. I needed to identify Marketing employees who worked in offices in the East building.

SQL
SELECT *
FROM employees
WHERE department = 'Marketing'
AND office LIKE 'East%';
Explanation

This query retrieves employees who work in Marketing and in an East office. I used SELECT * to retrieve all data from the employees table. The first condition, department = 'Marketing', filters employees by department. The second condition, office LIKE 'East%', finds offices that start with East, such as East-178 or East-320. I used AND because both conditions need to be true.

05 / 06

Retrieve employees in Finance or Sales

Context

The security team needed to perform a different security update on computers used by employees in the Finance and Sales departments. I needed to identify employees who belonged to either of these departments.

SQL
SELECT *
FROM employees
WHERE department = 'Finance'
OR department = 'Sales';
Explanation

This query retrieves employees from the Finance or Sales departments. I used SELECT * to retrieve all data from the employees table. The WHERE clause checks the department column for two possible values. I used OR because an employee only needs to belong to either Finance or Sales to be included in the results.

06 / 06

Retrieve all employees not in IT

Context

Employees in the IT department had already received the security update. I needed to identify employees from all other departments who still needed the update.

SQL
SELECT *
FROM employees
WHERE department <> 'IT';
Explanation

This query retrieves all employees who are not in the IT department. I used SELECT * to retrieve all data from the employees table. The WHERE clause filters the results using the department column. I used <> because it means "not equal to," so employees whose department is exactly IT are excluded from the results.

Summary

In this project, I applied SQL filters to investigate real security scenarios: identifying failed login attempts outside business hours, filtering suspicious activity by date and by country, and locating employees by department and office location to coordinate security updates. I practiced using WHERE, AND, OR, LIKE, NOT LIKE, the <> operator, and the % wildcard to build precise queries against larger datasets — a core skill for examining logs and system records within a SOC.
